# 概念
CAD
    Computer-Aided Design
    计算机辅助设计
    负责设计零件
    所有能做3D模型的软件都可以看成CAD软件
CAM
    Computer-Aided Manufacturing,
    计算机辅助制造
    负责把设计好的模型转换成生产的指令, 直接控制数控机床这些设备
    切片软件是负责将模型翻译给打印机, 不是用是直接创建模型的
Direct Modeling
    直接建模
    无底层蓝图, 直接推拉物体的形状, 模型复杂之后修改早期的步骤非常困难, 因为后续的步骤全部依赖前步骤, 甚至改起来不如直接重画
Parametric Modeling
    参数化建模
    靠参数生成精准模型
    可以随时调整早期参数,一般不会影响后续步骤
    例如付费的SolidWorks和CATIA, 免费的FreeCAD, Onshape, Fusion
    以3D打印为目的的建议使用参数化建模, 除非设计尺寸非常宽松如手办
        很多3D模型的目标, 是在电脑里渲染出好看的虚拟物品, 而不是将它变成实物

# fusion
## 脱机工作
Fusion 360 服务器基本都在美国 / 欧洲的数据中心, 中国国内几乎没有完整的Fusion云节点
其管理同步校验属于疯狂小请求,一丢包反复重试,转圈装死
脱机后只算几何,不负责“管理”, 全部变成本地计算,本地文件,本地历史
    建档,建模,草图,装配,本地渲染,修改历史特征这些不受影响
    不能打开没完整缓存过的文件,不能建夹改名删档,仿真版控等云相关
    强制至少每14天一次联网验号
设计高峰期脱机干活, 网络顺的时候联机同步, 定期导出F3D

### 关于三角面
三角形有一个工程界的超能力：任何曲面，都能用足够多的三角形逼近
    电脑最擅长的就是画三角形,算三角形,所以显卡,打印机,游戏引擎全部都吃三角面
    三角形越小,文件越大,表面越光滑
    圆孔在STL里只是很多很小的直线段围成的假圆
从 STEP → STL 是单向的, 可以降级, 但几乎不可能完美升回来
    所以设计阶段：实体（STEP / F3D）, 制造 / 打印：三角面（STL / 3MF）

## ice tray
操作流程
    拉伸切除 → 得到方坑
    用「时间轴中的拉伸特征」作为选择对象做圆角
    阵列 → 对象类型选“特征”
    选中：拉伸 + 圆角
    计算类型选“相同”或“已调整”
结果：
    方坑被阵列，但圆角没有阵列
但：
    改成 已优化 → 正常
    或者特征圆角改为“手选五个面” → 任何计算方式都正常
选“特征”来圆角
    对这个拉伸生成的边进行圆角
        圆角依赖的是“原始那一次拉伸特征的拓扑结果”。
        它不是独立几何，而是绑定在“那一个拉伸实例”的拓扑ID上。
    三种计算方式
        已优化（Optimized）
            只复制几何结果
            不重新计算内部依赖
            类似“几何复制”
                最稳定, 不重新识别边, 所以圆角能保留
        相同（Identical）
            复制特征
            重新计算特征
            但仍基于原始依赖
                圆角依赖的是“那一个拉伸特征的边”。
                当阵列复制时, 拉伸特征被复制
                但圆角仍然引用原始特征的边
                新拉伸产生的边并没有被重新关联, 所以圆角没有作用到新实例
        已调整（Adjust）
            完全重新计算
            重新识别几何
                但因为你的圆角引用的是“特征级边”
                Fusion 无法在新实例中找到等价边的稳定映射, 所以圆角丢失。
    用“特征引用”做圆角，阵列时圆角仍然指向原始特征，而不是阵列生成的新特征。
        Fusion 的参数化系统是基于拓扑ID的，而不是智能几何识别
手动选五个面来圆角
    对这些具体面生成的边做圆角
    它是几何级引用
    阵列复制时几何拓扑一起复制
    不依赖原始拉伸特征ID
    无论 Optimized / Identical / Adjust 都能正常复制
最佳实践
    先阵列再统一圆角, 或者圆角时手选几何（不要选特征）
    阵列内部不要使用“依赖上游特征拓扑ID”的二级特征, 尤其是圆角,倒角,分割,壳,这些都高度依赖拓扑稳定性。
    能选面，就不要选特征；
    能选边，就不要选结果集。
        面/边引用 → 可重建
        特征引用 → 极易在阵列、镜像、参数修改后失效
    “跟着特征走”的圆角，只认那一次拉伸；
    “跟着几何走”的圆角，只认长得一样的面。
    圆角在参数建模里永远是“最后特征”

用“特征选面 + 阵列计算=已优化”得到了想要的视觉结果, 在大多数情况下对最终实体几何没有负面影响，因为制造只关心最终几何, 但会影响后期可编辑性和参数稳定性。
什么时候可以放心用“已优化”
    情况1：已经接近最终设计阶段, 模型基本定型，不会大改结构。
    情况2：阵列数量很多, 比如 50、100 个坑。计算更快
什么时候不建议用“已优化”
    还在早期设计阶段
    结构会频繁改
    是参数化驱动结构（公式控制数量）
    作为模板反复复用
        那么建议先阵列基础结构，再统一做圆角, 这样参数链最干净。
    开发阶段
        优先保证参数清晰
        少用优化
        多保证历史可重算
    发布/定稿阶段
        可以改为优化
        甚至合并特征
        甚至删除历史
        因为制造只关心最终几何。

## doorstop
20260103202902.webp
工程草图里，优先标“投影尺寸”，最后才是“真实长度”
    线段实际长度 = 30时
        锁定了两端点的“真实空间距离”
        之后只能在固定的底点和固定的上边位置之间，强行塞一条长度正好30的线
        而此时角度已经被几何关系“隐式决定”了, 再去强行指定12°不可能同时满足, 于是报约束失败
    当改标Y方向投影 = 30时
        锁定的是垂直高度差, 而不是线段真实长度。
        在这种自由度下根据垂直高度30和角度12自动计算出线段真实长度
