# 同义词词库维护手册（`cilin.txt` / `synonyms_custom.json` / `oov_report.txt`）

本站点搜索引擎的同义扩展产物 `../src/js/synonyms.js`（算法版本 `cilin-1hop-df-v5.0`）由 `gen.jar` 中的 `SynonymBuilder` 自动构建，采用**方案 A（全量词林保留 + 公开语料 DF 软加权 + 现代词独占覆盖）**，无需手工编辑生成后的 `synonyms.js`。

---

## 1. 文件布局与职责

| 文件路径（相对构建目录） | 维护方式 | 是否公开部署 | 说明 |
| :--- | :--- | :--- | :--- |
| `cilin.txt` | **只读源数据** | 否 | 哈工大同义词词林扩展版底库，日常不直接修改 |
| `synonyms_custom.json` | **人工主维护** | 否 | 现代双向词组、单向别名、技术词停扩与词林清洗规则 |
| `oov_report.txt` | **自动生成** | **严禁** | 本地新词雷达报告，定期浏览并反哺 `synonyms_custom.json` |
| `synonyms.sha256` | **自动生成** | 否 | 双重哈希防抖状态（`rawSha\|outSha`），用于跳过无变化构建 |
| `synonyms.raw.js` | **自动生成** | 否 | 未压缩源码，便于人工核对清洗结果与 DF 分桶标注 |
| `../src/js/synonyms.js` | **自动生成** | **是** | 经 `esbuild` 压缩的最终产物，由 `core-list.js` 与 `sw.js` 追踪更新 |

> **关键提醒**：请勿在 `../src/js/raw/` 下放置 `synonyms.js`，否则 `CLI.bat` 第一阶段的增量编译会覆盖 `SynonymBuilder` 生成的产物。

## 2. 构建与调试命令

### 日常完整构建
直接通过 `CLI.bat` 执行 `[0] gen`（或 `[6] gen_and_push`）：
1. `Generator.run()` 仅收集**公开、非排除 HTML** 的「标题 + 剔除 `#anchor` 后的正文」，并用公开媒体文件名补充 `DF = 1`。
2. **隐私硬隔离**：`__` 前缀私密页面（`shadowDataMap`）绝不参与 DF 统计与 OOV 扫描，写私密日记不会泄露词汇指纹，也不会引起公网 `synonyms.js` 哈希抖动。
3. 在 `generateManifest()` 之前执行 `SynonymBuilder.buildIfNeeded()`：仅当词林、规则、DF 分桶或磁盘产物真正发生变化时，才调用 `esbuild` 重编 `../src/js/synonyms.js`，新 CRC32 哈希会在同轮写入 `core-list.js` 并触发客户端 `sw.js` 清空旧 `search_cache`。

### 仅调试词库（秒级重建）
修改 `synonyms_custom.json` 后若只想快速验证产物、不走全站构建，在构建目录执行：
```bat
java -Dfile.encoding=UTF-8 -jar jar\gen.jar synonyms
```
该命令直接读取现有的 `../src/js/data/fat_data_*.json` 与 `lite_data.js` 完成 DF 统计、刷新 `oov_report.txt` 并按需重建 `../src/js/synonyms.js`（正式发布前仍需执行一次 `[0] gen` 以同步 `core-list.js` 清单哈希）。

### 强制重建
如果怀疑 `synonyms.sha256` 状态异常或需强刷输出，直接删除 `synonyms.sha256` 后重新运行构建即可。

## 3. `cilin.txt` 维护规范

### 原则：保持只读，补丁外置
**不要直接编辑 `cilin.txt`**。词林原文件的所有纠错（删脏词、拆粘连词、降级误归类行）统一记录在 `synonyms_custom.json` 中，保证规则可审计、可迁移。

### 格式与编码速查
每行格式为 `<7位编码><关系符> <词1> <词2> ...`：
* **`=`（等义行）**：参与近义扩展，所有两字及以上词互通。
* **`#`（同类行）** / **`@`（独立词）**：**不参与**近义扩展，但保留在全词表 `lexicon` 中，用于复合词 DP 分词边界保护与上下文消歧。
* **构建期自动清洗**：自动剔除单字词、全角转半角、拆分含 `…` / `，` 的条目、剥离中文词尾残余拉丁字符。

编写自定义 `groups` 时，可参考以下常用 **5 位分类码（`c5`）** 参与复合词上下文消歧（未填或不足 5 位时默认 `Zz00Z`）：

| 领域 | 推荐 `c5` | 对应词林语义类 |
| :--- | :--- | :--- |
| AI / 算法 / 学科理论 | `Dk01A` | 知识 / 学科 / 理论 |
| 网络 / 软件 / 编程 / 系统 | `Dd06A` | 系统 / 结构 / 逻辑 |
| 电脑 / 电机 / 机械整机 | `Bo01A` | 机器 / 机械 |
| 手机 / 元器件 / 电路 / 工控 | `Bo04A` | 电器 / 电子器件 |
| 电影 / 剧集 / 视频 / 动漫 | `Dk29D` | 影视作品 |
| 音乐 / 歌曲 / 配乐 | `Dk28A` / `Dk28B` | 音乐 / 歌曲 |
| 书籍 / 文档 / 数字内容 | `Dk17A` | 书刊 / 图文 |
| 徒步 / 登山 | `Fb01A` | 行走动作 |
| 露营 / 户外活动 | `Hj01B` | 露宿 / 户外 |
| 帐篷 / 背包 / 服装 / 鞋 | `Bp29D` / `Bp11A` / `Bq03A` / `Bq05B` | 对应器物与服饰 |
| 金融 / 社保 / 经济 | `Dj04A` | 经济 / 财税 |

## 4. `synonyms_custom.json` 维护手册

文件为标准 UTF-8 JSON（**不支持注释与尾逗号**），包含 6 个顶层字段：

```json
{
  "dropEqCodes": ["..."],
  "pruneWords": { "code7": ["词1", "词2"] },
  "splitFixes": { "粘连错词": ["词1", "词2"] },
  "stopExpand": ["指针", "堆栈"],
  "groups": [
    { "c5": "Bo01A", "words": ["电动机", "电机", "马达"] },
    { "c5": "Dd06A", "exclusive": false, "words": ["报错", "异常"] }
  ],
  "aliases": {
    "梯子": ["VPN", "翻墙", "代理"]
  }
}
```

### 字段详解

1. **`groups`（现代双向同义词组）**
   * 组内任意词互相扩展，命中权重固定 `88`（`tier: 1`，`maxNoise: 0`）。
   * **`exclusive` 默认为 `true`（独占覆盖）**：构建期会自动把组内全部词从词林冲突 `=` 行中剥离（并保留到 `@` 词表保护分词），彻底杜绝词林旧义污染（例如定义 `["电动机", "电机", "马达"]` 后，查 `电机` 不再混入词林的 `发电机`）。
   * 若希望保留词林既有同义词、仅做增量补充，显式设置 `"exclusive": false`（例如 `["报错", "异常"]`）。
   * 长度 `< 2` 的单字词会被自动忽略；大小写不敏感去重，建议英文缩写按习惯大小写书写（如 `LLM`、`MOSFET`、`SQLite`）。

2. **`aliases`（单向别名）**
   * 格式 `"查询词": ["目标词1", "目标词2"]`，命中权重 `85`（`tier: 1`，`maxNoise: 0`）。
   * **单向生效**：搜键名会召回目标词，但搜目标词**不会**反向召回键名。
   * 适用场景：黑话/俗称（`梯子 -> VPN/翻墙/代理`、`油管 -> YouTube`）、缩写防泛化（`SD -> 扩散模型/Stable Diffusion`）、上下位归类（`美剧/日剧/港剧 -> 电视剧/剧集`、`ComfyUI -> 扩散模型/文生图`）。

3. **`stopExpand`（全局停扩黑名单）**
   * 列出的词会被全局从词林 `=` 行剥离，并移入 `@` 词表维持复合词分词边界。
   * 适用场景：现代技术单义词或极易在词林里严重漂移的词（如 `指针` 不扩 `指南针/表针`，`堆栈` 不扩 `仓库`，`对象` 不扩 `情人`，`进程` 不扩 `过程`）。
   * 注意：`stopExpand` 仅屏蔽**词林** `=` 扩展，不影响你在 `groups` 或 `aliases` 中显式配置的扩展。

4. **`dropEqCodes`（词林整行降级）**
   * 填入 7 位词林编码（如 `"Bh08A38"` 对应 `川军 大黄 将军`），将整行由 `=` 降级为 `@`，整组停止互扩但词表仍保留。
   * 适用场景：词林原数据本身把反义词、不同物种、不同药品误归为同义行。

5. **`pruneWords`（按行精准剔词）**
   * 格式 `"7位编码": ["离群词1", "离群词2"]`，仅从指定词林行中删除个别噪声词，保留该行其余有效同义词（如保留 `日光灯/荧光灯`，仅剔除 `白炽灯`）。

6. **`splitFixes`（修复粘连错词）**
   * 格式 `"原始粘连串": ["拆分词1", "拆分词2"]`，用于修复 `cilin.txt` 中漏空格导致的连写词（如 `"保险丝冰箱": ["保险丝", "冰箱"]`）。

### 常见维护决策速查

| 遇到的问题 | 推荐处理方式 |
| :--- | :--- |
| 搜技术词 `X` 扩出一堆无关古典词/日常词 | 将 `X` 加入 `stopExpand` |
| 搜现代词 `X` 想互通 `Y`（含中英），且不想受词林旧义干扰 | 加进 `groups`（默认 `exclusive: true`） |
| 搜简称/俗称/具体工具 `X` 想顺带查出 `Y`，但搜 `Y` 不想混进 `X` | 加进 `aliases`：`{"X": ["Y"]}` |
| 词林某一行里混进了 1~2 个错词（如 `青蛙` 行混进 `蝌蚪`） | 在 `cilin.txt` 查到 7 位码，填入 `pruneWords` |
| 词林整行都是伪同义/反义词（如 `抗体 抗原`、`川军 大黄 将军`） | 查到 7 位码，填入 `dropEqCodes` |

## 5. `oov_report.txt` 新词雷达使用指南

### 生成规则
每次运行 `gen` 或 `java -jar jar\gen.jar synonyms` 时自动刷新 `oov_report.txt`：
* **数据来源**：仅来自公开、非排除的 HTML（已去 `#anchor`），不包含任何 `__` 私密页面。
* **统计方法**：用全量词林 + 自定义词表执行正向最大匹配（FMM）扫描后，从**未收录片段**中提取：
  1. **英文/技术术语 Top 60**：过滤 URL、常见英文停用词与代码保留字、纯小写 2 字母词。
  2. **中文候选词 Top 60**：2~4 字连续未命中中文串，过滤首尾虚字，并自动抑制被更高频长词吸收的残片子串。
* **动态阈值**：公开文档数 `>= 50` 时要求 `DF >= 2, TF >= 3`；文档数 `< 50` 时降为 `DF >= 1, TF >= 2`。

### 推荐月度维护流程（约 5 分钟）
1. 打开 `oov_report.txt`，只关注**你未来真会拿来搜索、且存在同义表达或中英对应**的高频词（人名、古籍专名、代码变量名直接忽略）。
2. 将挑出的词补入 `synonyms_custom.json` 的 `groups`（双向）或 `aliases`（单向）。
3. 运行 `java -jar jar\gen.jar synonyms`，检查日志无报错，且可通过 `synonyms.raw.js` 核对已生效的规则与 DF 分桶。
4. 确认无误后在下次发布前运行 `[0] gen` 同步清单。

## 6. 附录：DF 分桶权重表与故障排查

### DF 软加权分桶（写入 `CILIN_RAW_DATA` 的 `:1`~`:6` 后缀）

| 标记 | 条件（`N` 为公开 HTML 总数） | 候选词乘数 | 义项消歧贡献 | 含义 |
| :--- | :--- | :---: | :---: | :--- |
| 无后缀 | `DF = 0` | `0.62` | `0.00` | 公网未出现；保留作查询入口，私密页与评论靠 Bloom 兜底 |
| `:1` | `DF = 1` | `1.00` | `+0.25` | 孤篇专词或公开媒体标题词 |
| `:2` | `2 <= DF <= 3` | `1.12` | `+0.45` | 低频高区分度活词 |
| `:3` | `DF >= 4` 且 `DF/N <= 8%` | `1.18` | `+0.60` | 黄金主题活词（权重峰值） |
| `:4` | `8% < DF/N <= 20%` | `1.00` | `+0.35` | 常见实词 |
| `:5` | `20% < DF/N <= 40%` | `0.68` | `+0.10` | 偏泛通用词（轻度降权） |
| `:6` | `DF/N > 40%` | `0.38` | `0.00` | 全站泛滥高频词（强降权，抑制噪声） |

### 常见问题排查
* **改完 `synonyms_custom.json` 后构建未生效**：查看控制台日志是否报 JSON 解析错误（常见原因：多写了尾逗号或混入注释）；确认无语法错误后若仍跳过，删除 `synonyms.sha256` 再跑一次。
* **某个词林垃圾扩展仍在出现**：在 `synonyms.raw.js` 中搜索该词，可直接看到它归属的 7 位编码与 `:1..:6` 分桶，再按第 4 节速查表加入 `stopExpand` / `pruneWords` / `dropEqCodes`。
* **自定义词没生效**：确认词长 `>= 2`（单字会被过滤），并确认该候选词在当前语料中确实存在（运行时 Worker 会用 Bloom 过滤语料中完全未出现的候选词，以避免无效扫描）。
